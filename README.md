# MAX чат через GREEN-API

React-чат для отправки и получения текстовых сообщений в MAX.

## Локальный запуск

Нужен Node.js 20.19+ или 22.12+.

```bash
npm install
npm run dev
```

Откройте `http://127.0.0.1:5173/` после запуска сервера. Для проверки сборки: `npm run build`.

## Публикация

Сайт публикуется через GitHub Pages по адресу [k-real-mh.github.io/green-api-max-chat](https://k-real-mh.github.io/green-api-max-chat/). В настройках репозитория выберите **Settings → Pages → Build and deployment → Source: GitHub Actions**. После отправки изменений в `main` workflow соберёт проект и опубликует папку `dist`.

Для использования чата на опубликованном сайте введите параметры своего инстанса GREEN-API. Токен не добавляется в репозиторий и не передаётся в GitHub Actions.

## Подготовка GREEN-API

1. Зарегистрируйтесь в [кабинете GREEN-API](https://console.green-api.com/), создайте инстанс MAX и авторизуйте его с аккаунтом MAX.
2. В настройках инстанса включите входящие уведомления (`incomingWebhook`) и оставьте `webhookUrl` пустым. [Описание HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/).
3. Скопируйте из кабинета `apiUrl`, `idInstance` и `apiTokenInstance` и введите их на первом экране приложения. Для проверки ответа потребуется второй аккаунт MAX.

Данные доступа не находятся в исходниках и не сохраняются в браузере. После обновления вкладки их нужно ввести снова. Приложение хранит чаты и сообщения только до закрытия или обновления вкладки, поэтому старую переписку не показывает.

Создание чата выполняется через `CheckAccount`, чтобы получить реальный `chatId`. Номера поддерживаются в международном формате РФ и Беларуси. Отправка использует `SendMessage`; прием — `ReceiveNotification` и `DeleteNotification`.

## Структура исходников

- `src/components/` — формы и части интерфейса;
- `src/api/` — запросы к GREEN-API и проверка вводимых данных;
- `src/hooks/` — состояние чатов и цикл получения уведомлений;
- `src/types/` — типы чата и ответов API;
- `src/styles/` — стили приложения.

Приложение делает запросы напрямую из браузера к `apiUrl` инстанса. Если браузер сообщает об ошибке CORS, для конкретного окружения потребуется HTTPS-прокси. Без рабочего инстанса сквозную проверку обмена сообщениями выполнить нельзя.
